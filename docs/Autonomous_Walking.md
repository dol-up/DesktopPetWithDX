# 자율 걷기 구현 현황

기준: 2026-10-02. 계획의 1~6단계인 판단 로직, 실제 좌우 이동, 방향 회전, 걷기 애니메이션 연결, 설정 UI·모델별 저장, 통합 검증을 구현했다.

## 1. 현재 사용 방법

1. 펫을 오른쪽 버튼으로 더블클릭해 설정 창을 연다.
2. **자율 걷기** 탭에서 걷기 클립을 선택한다. 자동 선택은 이름의 마지막 `|` 뒤가 `walk` 또는 `walking`인 클립을 찾는다. 다른 이름은 직접 지정한다.
3. ‘자율 걷기 사용’을 켜고 필요하면 이동 속도·걷기 배속·시간 범위·방향을 조정한다.
4. 저장하고 닫으면 바닥에서 잠시 대기한 뒤 걷는다.

처음 사용하는 모델의 기본값은 꺼짐이다. 펫을 클릭해 포커스를 준 뒤 `B` 키로도 켜거나 끈다. B 키와 체크박스는 같은 모델 설정을 변경하며, 정상 종료나 모델 변경 때 저장된다. 설정 창에 포커스가 있으면 펫 단축키를 처리하지 않는다.

기본 동작은 3~8초 대기, 방향 회전, 2~5초 이동, 정면 복귀, 다시 대기다. 기준 이동 속도는 초당 60픽셀이고 방향 회전은 0.3초다. 회전하는 동안 가로 이동은 멈춘다. 이동 시간이 남은 상태에서 화면 끝에 닿으면 멈춰서 반대쪽으로 돌고 남은 이동을 계속한다. 구간의 이동 시간을 모두 쓰면 정면으로 돌아온 뒤 새 대기 시간을 시작한다. 정면 복귀에도 ‘방향 전환 시간’을 사용한다.

이동 제어기가 `Moving`이면 `Walk` 클립을 반복 재생하고, 대기·방향 회전·정면 복귀 중에는 `Idle`을 재생한다. 기존 전환 시간으로 두 자세를 연결하며 매 프레임 클립을 재시작하지 않는다. 걷기 클립이 없거나 ‘재생 안 함’을 선택하면 자율 이동과 자동 방향 전환을 실행하지 않는다.

드래그, 우클릭 회전, K+L 수동 조작 모드, 설정 창 표시, 애니메이션 미리보기, 착지 애니메이션 중에는 자율 이동을 중단한다. 공중이거나 물리 정보를 얻지 못한 경우도 중단한다. 다시 가능해지면 새 대기 시간부터 시작한다. `R`은 수동 조작 모드에서 사용자 회전과 자동 회전을 모두 초기화한다.

자율 이동을 끄면 현재 방향을 유지한다. 모델 교체 시 자동 방향과 진행 중인 이동 계획을 초기화하고 해당 모델의 저장 설정을 복원한다. 마지막 창 위치는 기존 `last_model.txt` 경로로 저장된다.

```text
입력과 중단 조건
  → PetBehavior의 모델 설정·유효한 걷기 클립 확인
  → 기존 방향의 바닥으로 WindowPhysics::Prepare
  → 모니터 작업 영역과 고정된 가로 범위 확인

```

`WanderPhase`의 Waiting/Turning/Moving/Returning은 이동 제어기의 내부 단계다. Returning은 걷기 종료 후 정면으로 돌아오는 단계이며 별도 행동 상태는 추가하지 않는다. 애니메이션의 `PetState`는 Idle/Dragged/Falling/Landing/Walk의 5개다. 잡힘·낙하·착지는 Walk보다 우선한다. 기존 상태 번호 0~3을 유지하고 Walk를 4에 추가했다.

## 3. 좌표와 화면 경계

투명한 창의 너비 전체가 아니라, 모델의 바인드 자세를 기준으로 가로 범위를 계산한다. 사용자 회전까지 적용한 정점들을 Y축 주위의 원기둥으로 감싼 뒤 그 원기둥을 포함하는 상자의 모서리를 화면에 투영한다. 이 범위는 실제 자세보다 보수적이지만 모든 자동 yaw를 포함하므로 회전 중에도 경계가 바뀌지 않는다. 클립마다 팔이 움직이는 것도 경계 판정을 흔들지 않는다.

허용 창 X 좌표는 다음과 같다. 정수 창 좌표에 맞춰 왼쪽 한계는 올림, 오른쪽 한계는 내림한다.

```text
최소 X = ceil(작업 영역 왼쪽 - 클라이언트 X 오프셋 - 모델 범위 왼쪽)
최대 X = floor(작업 영역 오른쪽 - 클라이언트 X 오프셋 - 모델 범위 오른쪽)
```

모니터는 자율 이동이 가능한 동안 고정해서 투명 여백이 다른 모니터와 겹쳐도 바닥이 바뀌지 않게 한다. 사용자가 다시 잡거나 이동을 중단하면 다음 시작에서 모니터를 다시 선택한다. 화면 구성이 바뀌어 기존 모니터를 찾지 못하면 새 모니터를 조회한다. 음수 좌표도 그대로 처리한다.

크기나 작업 영역 변경으로 현재 X가 범위를 벗어나면 가능한 범위로 한 번 보정한 뒤 대기한다. 모델이 작업 영역보다 넓어 이동 공간이 없으면 이동하지 않는다.

## 4. 회전과 바닥 접촉

공통 모델 행렬은 `정규화 × 사용자 quaternion 회전 × 자동 Y축 회전`이다. 자동 방향은 사용자 quaternion을 덮어쓰지 않으며 렌더링·피킹·바닥 계산이 같은 행렬을 사용한다.

기본 전방을 -Z로 간주하면 오른쪽은 -90도, 왼쪽은 +90도 yaw다. 설정의 ‘정면 방향 보정’으로 모델의 다른 정면 축을 보정한다. UI는 도 단위, `WanderSettings::forwardYawRadians`와 파일은 라디안 단위다. 각도는 가장 짧은 경로로 보간하고 `t²(3-2t)`로 시작과 끝을 부드럽게 한다.

걷기 종료 후 Returning의 목표 yaw는 `forwardYawRadians`다. 복귀가 끝나면 정면을 유지하며 대기한다. 사용자가 우클릭으로 만든 quaternion은 그대로 두므로 수동 회전을 지우지는 않는다. 복귀 도중 잡기·회전·공중 상태 등의 중단 조건이 생기면 현재 각도에서 계획을 취소한다. ‘방향 전환 시간’이 0이면 정면을 즉시 적용한다. B 키로 끄는 등의 강제 중단은 기존처럼 현재 각도를 유지한다.

회전하면 원근 투영 때문에 바닥의 화면 Y가 달라질 수 있다. `Prepare`에서 이미 접지한 것으로 판정한 프레임은 `Apply`에서 새 바닥 높이에 맞춰 창 Y도 보정한다. 접촉 상태를 유지하므로 회전할 때마다 낙하·착지 이벤트를 만들지 않는다.

가로·세로 이동은 `SWP_NOSIZE | SWP_NOZORDER | SWP_NOACTIVATE`로 적용한다. 준비 이후 외부에서 창 위치가 바뀐 경우에는 오래된 좌표를 적용하지 않는다. 위치 적용이 실패하면 중력·이동 계획을 초기화하고 자동 회전을 이전 각도로 되돌린다.

## 5. 걷기 클립과 속도 연결

걷기는 길이가 양수이고 노드 애니메이션으로 지원되는 클립만 선택할 수 있다. `Animator::HasPlanarRootMotion`은 최상위 본의 전역 위치를 클립 시작과 끝에서 비교한다. 본이 없으면 최상위 애니메이션 채널 노드를 검사한다. 유의미한 X/Z 변위가 있으면 걷기 지정에서 제외한다. 검사는 재생 시간·자세·일시정지 상태를 바꾸지 않으며 모델 로딩 때 결과를 캐시한다. 일반 미리보기에서는 해당 클립을 확인할 수 있다.

이 검사는 누적 전진을 거르는 기준이다. 중간에 크게 이동했다가 끝에서 원위치로 돌아오는 클립까지 판별하지는 않는다. 모든 관절의 진행 방향이나 보폭을 자동으로 분석하거나 루트 모션을 추출하는 기능은 없다. 실제 제자리 걷기 동작을 선택해야 한다.

실제 가로 이동 속도는 다음 값이다.

```text
픽셀/초 = 기준 이동 속도 × Walk 재생 배속 × 클라이언트 높이 / 600
```

높이 600픽셀, 배속 1에서 기본 속도는 60픽셀/초다. 배속 2에서는 120픽셀/초, 높이 300픽셀에서는 30픽셀/초다. 걷기 배속을 바꿔도 클립 재생 시간과 진행 중인 이동 구간을 재시작하지 않는다. 모델마다 보폭이 달라 발이 미끄러져 보이면 기준 이동 속도를 조정한다. 발 고정 IK는 지원하지 않는다.

| 설정 화면 항목 | 범위·기본값 |
|---|---|
| 이동 속도 | 1~2000픽셀/초, 기본 60 |
| 걷기 배속 | 0.05~4배, 기본 1 |
| 대기 시간 범위 | UI 0~30초, 기본 3~8 |
| 걷는 시간 범위 | 0.1~60초, 기본 2~5 |
| 방향 전환 시간 | 시작·경계 반전·정면 복귀 공통, 0~2초, 기본 0.3 |
| 정면 방향 보정 | -180~180도, 기본 0 |

## 6. 모델별 저장과 이전 파일 호환

걷기 설정은 `PetAnimationSettings`에 함께 보관하며 `animation_settings.txt` 버전 2로 저장한다. 기존 상태의 선택·속도·반복·전환 시간과 걷기 클립, 활성화 여부, 위 이동 옵션이 모두 모델별 값이다. 파일 예시는 [런타임 문서의 저장 형식](Animation_Runtime.md#저장-파일-예시)을 참고한다.

버전 1 파일의 4개 상태를 그대로 읽고 새 Walk는 자동 선택·반복·배속 1, 자율 걷기는 꺼짐으로 채운다. 다음 저장부터 버전 2로 기록하며 다른 모델의 기존 설정도 보존한다. 지정 클립은 원본 이름과 중복 이름의 등장 순번으로 찾는다. 누락되거나 걷기용으로 사용할 수 없으면 그 상태를 자동 선택으로 되돌리고 알린다. 유효한 클립이 없으면 저장된 활성화 값이 있어도 이동하지 않는다.

저장 버튼, 변경 후 설정 창 닫기, 모델 변경 전, 정상 종료에 저장한다. 전체 값을 검사한 뒤 임시 파일을 쓰고 교체하며, 실패하면 기존 파일과 메모리 목록을 유지한다. ‘기본 설정으로 초기화’는 걷기 꺼짐과 이동 옵션도 기본값으로 되돌린다.

## 7. 검증 결과와 범위

[WanderControllerTests.cpp](../Tests/WanderControllerTests.cpp)는 대기와 회전, 30/60/144 FPS의 동일 이동 거리, 좌우 걷기 후 보정된 정면 복귀·대기 유지, 복귀 중 이동 정지·중단·회전 시간 0, 저속 소수 이동, 경계 반전, 음수 좌표, 중단 후 새 대기, 고정 난수, 각도 경계의 짧은 보간, 이동 도중 배속 변경, 잘못된 설정·시간을 검사한다.

[WalkingTests.cpp](../Tests/WalkingTests.cpp)는 Walk의 자동·직접 선택, 루트 전진 클립 제외, 상태 우선순위, 재생 시간 유지, 클립 제거 시 중단, 구형 파일 변환·모델 간 설정 보존·클립 순서 변경·잘못된 파일을 검사한다.

[AutonomousMotionTests.cpp](../Tests/AutonomousMotionTests.cpp)는 보이지 않는 Win32 창에서 준비/적용 분리, 두 축의 이동, 회전 중 바닥 보정, 중단, 오래된 창 좌표·큰 이동량 거부를 검사한다. 모델 경로를 전달하면 WARP 렌더러와 실제 모델을 사용해 좌우 이동과 Walk 재생, 정면 복귀 중 Idle·가로 이동 정지·접지 유지, 사용자 quaternion 보존, 바닥 안정성, 잡기·미리보기·설정 창 중단, 배속·크기에 따른 실제 이동량을 검사한다. 걷기 클립이 없는 모델은 이동·자동 회전이 실행되지 않는지 확인한다.

[SettingsWindowTests.cpp](../Tests/SettingsWindowTests.cpp)는 숨긴 창에 실제 ImGui 입력을 넣어 탭 전환, 활성화 체크박스, 저장 버튼, 모델별 복원을 검사한다. 걷기가 없는 모델의 활성화 제한과 창 크기 변경·닫기 저장·미리보기 종료도 확인한다. 두 탭의 렌더링 이미지를 확인했다.

메인 앱과 테스트의 Debug/x64 빌드가 통과했다. 로컬 FBX 7개 중 George·Leela·Mike·Stan은 실제 걷기 연결을, AgnesTachyon·Kazusa·Mambo는 클립이 없어 이동하지 않는 처리를 통과했다. 기존 74개 클립의 샘플링·스키닝·피킹·WARP 렌더링과 설정 검사도 통과했다.

테스트 실행 방법은 [애니메이션 런타임의 빌드와 검증](Animation_Runtime.md#10-빌드와-검증)을 따른다. 실제 데스크톱의 마우스·B 키 조작, 여러 모니터 사이의 드래그·화면 구성 변경, 앱 재실행 후 복원은 별도 수동 확인 대상이다. 자동 검사 결과가 모든 모니터·DPI 환경의 동작을 보장하지는 않는다.
