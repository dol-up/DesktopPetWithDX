# 애니메이션 런타임

기준: 2026-10-02의 현재 작업 코드. 애니메이션 클립 로딩, 스켈레톤 구성, 자세 계산, GPU 스키닝, 행동 상태 전환, ImGui 설정, 모델별 저장·복원, 전환 보간과 자율 걷기 1~6단계를 구현했다. 자율 걷기는 판단·이동·방향에 Walk 재생, 설정 UI·저장, 통합 검증을 연결한 상태다.

이 문서는 실제 동작과 코드의 연결을 설명한다. 자율 이동의 사용 방법과 좌표 처리는 [자율 걷기](Autonomous_Walking.md), 확인이 남은 항목은 [구현 현황](TODO.md)을 참고한다.

## 1. 설정 화면 사용 방법

펫을 마우스 오른쪽 버튼으로 더블클릭하면 별도 설정 창이 열린다. **애니메이션**과 **자율 걷기** 탭으로 나뉘며 설정 창을 열어도 펫의 렌더링은 계속된다. 내용 영역은 스크롤되고 저장 버튼은 아래에 유지된다.

| 항목 | 동작 |
|---|---|
| 대기·잡힘·낙하·착지·걷기의 클립 | 자동 선택, 재생 안 함, 특정 클립 중 선택 |
| 상태별 속도 | 0.05~4배 |
| 상태별 반복 | 대기·잡힘·낙하에서 설정 가능. 착지는 한 번, 걷기는 반복 재생으로 고정 |
| 전환 시간 | 0~2초. 기본값 0.15초이며, 0초는 즉시 전환 |
| 클립 미리보기 | 클립 선택, 반복·속도 변경, 처음부터 재생, 일시정지·계속, 재생 위치 이동 |
| 자동 동작으로 복귀 | 미리보기를 끝내고 행동 상태에 따른 재생으로 복귀 |
| 자율 걷기 | 유효한 걷기 클립이 있을 때 활성화, 이동 속도·배속·시간·방향 보정 설정 |
| 저장 | 현재 모델의 애니메이션과 걷기 설정 저장 |
| 기본 설정으로 초기화 | 클립·속도·반복·전환 시간과 걷기 꺼짐·이동 옵션을 기본값으로 되돌림 |

변경 사항은 즉시 적용된다. 다른 상태의 설정을 수정하거나 현재 상태의 속도만 바꿔도 재생 시간이 매번 처음으로 돌아가지는 않는다.

‘재생 안 함’은 바인드 자세, 즉 모델이 가진 기본 자세를 선택한다. 자동 선택에서 클립이 없을 때 사용하는 대체 동작과 구분해야 한다. 걷기를 ‘재생 안 함’으로 설정하면 자율 이동도 실행하지 않는다.

미리보기 중에는 중력을 멈추고 행동 상태의 클립 선택을 건너뛴다. 일시정지는 클립 시간과 전환 보간을 함께 멈춘다. 재생 위치를 직접 옮기면 진행 중인 보간을 취소하고 지정한 시점의 자세를 정확히 표시한다. 자동 동작으로 복귀하거나 설정 창을 닫으면 미리보기가 종료된다.

키보드 단축키는 펫 창이 전경 창일 때만 처리한다. 설정 창에서 입력하는 키가 모델 변경이나 수동 이동을 실행하지 않도록 분리한 것이다.

## 3. 클립과 스켈레톤 로딩

`LoadAnimationClips`는 이름, 원본 인덱스, 길이, 위치·회전·크기 키, 키 구간 밖의 처리 방식을 복사한다. `Assimp::Importer`가 소멸한 뒤에도 이 데이터는 유효하다.

시간 변환은 `초 = 키의 tick / ticksPerSecond`이다. 파일에 `ticksPerSecond`가 없으면 프로젝트 정책으로 25를 사용한다. 이 값은 화면 렌더링 FPS가 아니다. 마지막 키가 선언된 길이를 넘으면 클립 길이를 그 키까지 늘린다. 유한하지 않은 값이나 시간 순서가 뒤집힌 키는 거부한다.

`LoadSkeleton`은 본뿐 아니라 부모 변환에 필요한 일반 노드도 저장한다. 부모가 자식보다 먼저 배열에 들어가므로 순차적으로 전역 행렬을 계산할 수 있다. 본의 offset 행렬은 메시마다 따로 보존한다. 한 메시를 여러 노드가 사용하는 경우도 기록한다.

`BindAnimationChannels`는 각 채널 이름을 노드 인덱스에 연결한다. 이름이 없거나 같은 이름의 노드가 여러 개여서 연결 대상을 확정할 수 없으면 오류를 낸다.

현재 재생 대상은 노드 변환 애니메이션이다. 메시 교체·모프 채널 수는 기록하지만 해당 채널을 포함한 클립은 행동 설정과 미리보기의 재생 대상에서 제외한다. 애니메이션이 없는 모델은 바인드 자세로 표시한다.

## 4. 행동 상태와 자동 선택

| 상태 | 진입 조건 | 자동으로 찾는 이름 | 클립이 없을 때 |
|---|---|---|---|
| `Idle` 대기 | 바닥에 있음, 회전·수동 조작 중, 착지 재생 종료 | `idle` | 처음 발견한 지원 가능한 노드 클립. 모두 없으면 바인드 자세 |
| `Dragged` 잡힘 | 마우스로 잡고 있음 | `dragged`, `held`, `grabbed`, `pickup` 순 | 대기에 지정된 클립 사용 |
| `Falling` 낙하 | 물리가 유효하고 바닥에 닿지 않음 | `falling`, `fall` 순 | 대기에 지정된 클립 사용 |
| `Landing` 착지 | 낙하 후 접지 이벤트 발생 | `landing`, `land` 순 | 착지 재생을 건너뛰고 대기로 복귀 |
| `Walk` 걷기 | 바닥에서 자율 이동 제어기가 Moving이며 걷기 설정이 유효함 | `walk`, `walking` 순 | 자율 이동·자동 회전 중단 |

자동 검색은 이름의 마지막 `|` 뒤 부분을 사용하고 ASCII 대소문자를 구분하지 않는다. 예를 들어 `RobotArmature|Pickup`은 잡힘 상태에 연결된다. 착지·걷기 클립의 길이는 0보다 커야 한다. 특정 클립을 직접 지정하면 이름과 관계없이 사용할 수 있다. 걷기는 시작/끝 루트의 X/Z 변위가 유의미한 클립을 추가로 제외한다. 이 기준과 한계는 [자율 걷기 문서](Autonomous_Walking.md#5-걷기-클립과-속도-연결)를 참고한다.

상태 처리의 우선순위는 다음과 같다.

1. 미리보기 중이면 미리보기 재생만 갱신한다.
2. 잡고 있으면 물리 중지 여부와 관계없이 잡힘 상태를 선택한다.
3. 회전·수동 조작으로 물리를 중지했다면 대기를 선택한다.
4. 물리 결과가 유효하고 공중이면 낙하를 선택한다.
5. 바닥에서 아직 끝나지 않은 착지 재생은 유지한다.
6. 새 접지 이벤트와 사용 가능한 착지 클립이 있으면 착지를 시작한다.
7. 자율 이동 중이고 활성화 설정·걷기 클립이 유효하면 걷기를 선택한다.
8. 나머지 유효한 바닥 상태는 대기로 돌아간다.

물리 결과를 얻지 못한 프레임에는 직전 행동 상태를 유지한다. 착지 중 다시 잡거나 낙하하면 그 행동이 착지를 중단한다. 시작부터 바닥에 있거나 바닥에서 드래그를 놓는 것만으로는 착지를 재생하지 않는다.

자동 대체로 같은 반복 클립을 계속 사용하는 경우에는 상태가 바뀌어도 재생 시간을 유지한다. 반복을 끈 상태는 해당 행동 진입 후 한 번 재생하고 끝 자세를 유지한다. 착지만 재생이 끝나면 대기로 돌아간다. 걷기는 반복으로 고정하며 대기·방향 회전·걷기 종료 후 정면 복귀 중에는 Idle로 연결한다. Walk에 유효한 클립이 없을 때 대기 클립으로 이동을 대체하지 않는다.

`GravitySimulation`은 접지 결과를 `grounded`, 새 착지 이벤트를 `justLanded`로 구분한다. 창 좌표는 정수이고 투영한 모델 하단은 소수이므로 바닥까지 거리가 1픽셀 이하이면 접지로 취급한다. 이 허용 오차가 없으면 작은 틈 때문에 낙하와 착지가 반복될 수 있다.

## 5. 자세 계산과 전환 보간

`Animator`는 위치·크기에 선형 보간, 회전에 quaternion slerp를 사용한다. 특정 트랙이 없으면 해당 노드의 바인드 값을 사용한다. 키 구간 밖에서는 저장된 `DefaultPose`, `Constant`, `Linear`, `Repeat` 규칙을 적용한다.

클립 전환은 현재 화면에 보이는 로컬 자세를 복사해서 출발점으로 삼는다. 목적지 클립의 시간은 진행시키면서 위치·크기를 보간하고 회전은 slerp로 연결한다. 보간한 로컬 행렬에서 부모·자식의 전역 행렬과 본 행렬을 다시 계산한다.

전환 도중 다른 전환이 시작되면 그 순간 보이는 중간 자세를 새 출발점으로 삼는다. 바인드 자세로 돌아가는 전환도 재생 중인 클립 없이 진행할 수 있다. 영향을 받지 않는 행렬은 그대로 유지하며, 달라지는 행렬은 이동·회전·크기(TRS)로 분해한다.

이 구현은 현재 자세에서 새 클립으로 연결하는 방식이다. 이전 클립의 시간을 계속 진행시키며 두 클립을 동시에 재생하는 구조는 아니다. 전단 변환(shear)의 애니메이션, 루트 모션 추출, 발을 바닥에 고정하는 IK는 지원하지 않는다.

## 6. 행렬과 GPU 스키닝의 규칙

스켈레톤 행렬은 Assimp의 행 우선 저장과 열벡터 연산 규칙을 유지한다. 평행이동은 16개 원소 중 인덱스 3·7·11에 있다.

```text
전역 노드 행렬 = 부모의 전역 행렬 × 자신의 로컬 행렬
본 행렬       = 본 노드의 전역 행렬 × 메시별 offset 행렬
스키닝 위치   = Σ(가중치 × 팔레트 행렬 × 정점 위치)
```

같은 본을 여러 메시가 사용해도 offset은 합치지 않는다. 메시 인스턴스에는 기준 인스턴스와 현재 인스턴스 사이의 변환을 추가로 반영한다.

GPU 정점은 같은 본의 중복 가중치를 먼저 합친 뒤 큰 가중치 4개를 골라 합이 1이 되도록 정규화한다. 원본의 모든 양수 가중치는 스켈레톤 데이터에 남아 있지만, 실제 GPU 재생과 CPU 피킹은 같은 4개를 사용한다. 가중치가 없는 정점은 본 0에 붙이지 않고 메시 노드를 따르는 팔레트 항목을 사용한다.

현재 `Vertex`는 68바이트이며 인덱스는 `std::uint32_t`와 `DXGI_FORMAT_R32_UINT`를 사용한다.

| 셰이더 입력 | 자료형 | 바이트 위치 |
|---|---|---|
| `POSITION` | `float3` | 0 |
| `COLOR` | `float4` | 12 |
| `TEXCOORD0` | `float2` | 28 |
| `BLENDINDICES0` | `uint4` | 36 |
| `BLENDWEIGHT0` | `float4` | 52 |

본 팔레트는 구조화 버퍼(`StructuredBuffer`)와 SRV로 전달한다. 256개로 고정된 본 배열은 없지만 Direct3D 자원 크기와 메모리 한계는 적용된다.

[Skinning.hlsli](../Asset/Shaders/Skinning.hlsli)는 팔레트를 `row_major`로 읽고 `행렬 × 열벡터`로 스키닝한다. 이어 [Shader.hlsl](../Asset/Shaders/Shader.hlsl)은 기존 MVP 경로의 `행벡터 × 행렬` 규칙을 사용한다. MVP에 사용하는 CPU 전치와 스켈레톤 행렬의 전달 방식을 섞지 않아야 한다.

본 팔레트는 정점 셰이더의 `t0`, 재질 텍스처는 픽셀 셰이더의 `t0`에 연결된다. 같은 번호지만 서로 다른 셰이더 단계의 자원 슬롯이다.

정규화 크기와 중심은 스키닝한 바인드 자세에서 한 번 계산한다. 파일의 노드 계층이 축 변환을 제공하므로 예전의 일괄 X축 90도 회전은 적용하지 않는다. 사용자 quaternion 회전은 그 뒤에 적용한다.

## 7. 피킹과 바닥 기준을 구분하는 이유

`SkinVertices`는 GPU와 같은 가중치·팔레트로 현재 자세의 CPU 정점을 계산한다. `Animator::GetPoseRevision`이 바뀌면 팔레트·피킹·AABB 캐시를 다시 계산하고, 피킹 정점은 요청할 때만 갱신한다. 따라서 재생·정지·시간 이동·전환 보간 후에도 보이는 자세와 피킹 형상이 연결된다.

바닥 계산에는 로딩 시 보관한 바인드 자세의 정점인 `groundingVertices`를 사용한다. 매 프레임 움직이는 발끝으로 창 위치를 보정하면 애니메이션 때문에 창 자체가 위아래로 흔들릴 수 있기 때문이다. 회전이나 창 크기가 바뀌면 투영한 바닥 위치 캐시를 갱신한다.

이 기준은 안정적인 창 배치용이다. 애니메이션에서 발을 들면 시각적으로 발이 바닥에서 떨어질 수 있다. 루트 노드 이동도 데스크톱 창 이동으로 추출하지 않으므로 제자리 재생용 클립이 적합하다.

피킹은 텍스처 알파를 검사하지 않는다. 삼각형의 투명 영역도 클릭될 수 있다.

## 8. 설정과 마지막 위치의 저장

두 파일은 프로그램을 실행한 작업 폴더에 생성되며 Git 추적에서 제외한다.

| 파일 | 내용 | 저장 시점 |
|---|---|---|
| `last_model.txt` | 마지막 모델 경로와 창의 화면 좌표 | 시작 후, 모델 변경 후, 정상 종료 시 |
| `animation_settings.txt` | 여러 모델의 5개 상태 설정·전환 시간·걷기 활성화와 이동 옵션 | 저장 버튼, 변경 후 설정 창 닫기, 모델 변경 전, 정상 종료 시 |

`last_model.txt`는 첫 줄의 모델 경로를 유지하고 두 번째 줄에 `position x y`를 추가한다. 예전처럼 모델 경로만 있는 파일도 읽는다. 음수 모니터 좌표와 일부만 화면에 보이는 창 위치는 유지하며, 완전히 작업 영역 밖이면 가까운 모니터 작업 영역으로 보정한다. 복원 뒤에는 정상 물리가 재개되므로 공중의 위치라면 다시 낙하할 수 있다.

애니메이션 설정의 모델 키는 절대 경로로 정규화한 뒤 ASCII 대소문자를 통일한다. 모델 파일을 다른 경로로 옮기면 별도 모델 설정이 된다. 클립은 원본 이름과 같은 이름 중 몇 번째인지로 저장한다. 이름이 고유한 클립은 배열 순서가 바뀌어도 복원되지만, 중복 이름끼리의 순서가 바뀌면 같은 동작인지 보장할 수 없다.

복원할 클립이 사라지거나 지원되지 않으면 그 항목만 자동 선택으로 바꾸고 설정 화면에서 알린다. 잘못된 설정 파일은 오류를 표시하며 시작 시 기본 설정을 사용한다.

현재 저장 형식은 버전 2다. `wander` 행에 걷기 활성화, 기준 속도, 대기 최소·최대, 이동 최소·최대, 회전 시간, 정면 보정 라디안을 저장하고 `state 4`에 Walk 클립·배속·반복을 저장한다. 예전 버전 1의 4개 상태도 읽으며 새 Walk는 자동·배속 1·반복, 자율 걷기는 꺼짐으로 채운다. 다음 저장 때 다른 모델의 기존 설정을 포함해 버전 2로 기록한다.

애니메이션 설정은 새 모델 목록을 임시로 만든 후 `.tmp` 파일에 쓰고 `MoveFileExW`로 기존 파일을 교체한다. 쓰기 실패 시 기존 설정 파일과 메모리 목록을 유지한다. 마지막 모델·위치 파일은 이 저장기와 별도의 단순 스트림 저장 방식이다.

### 저장 파일 예시

아래는 파일 구조를 보여 주는 예시다. 경로는 실제 모델의 정규화된 절대 경로로 기록한다. 걷기 활성화 값이 1이어도 해당 모델에 유효한 Walk 클립이 없으면 이동하지 않는다.

```text
desktop_pet_animation 2
model "c:/models/pet.fbx"
transition 0.15
wander 1 60 3 8 2 5 0.3 0
state 0 0 1 1 "" 0
state 1 0 1 1 "" 0
state 2 0 1 1 "" 0
state 3 0 1 0 "" 0
state 4 0 1 1 "" 0
end
```

`state` 행의 필드는 상태 번호, 선택 방식, 재생 배속, 반복 여부, 원본 클립 이름, 같은 이름의 등장 순번이다. 상태는 Idle 0·Dragged 1·Falling 2·Landing 3·Walk 4, 선택 방식은 자동 0·재생 안 함 1·지정 2다. 등장 순번은 0부터 센다. 반복은 Landing에서 0, Walk에서 1로 고정한다.

`wander` 행은 활성화 여부, 기준 픽셀/초, 대기 최소·최대 초, 이동 최소·최대 초, 방향 전환 초, 정면 보정 라디안 순서다. Walk 배속은 `state 4`의 값이며 방향 전환 시간은 걷기 시작·경계 반전·정면 복귀에 함께 사용한다. 버전 1에는 `wander`와 `state 4`가 없다.

## 9. 설정 창과 텍스처 정책

설정 창은 별도 HWND와 swap chain을 사용하고 펫의 Direct3D device/context를 공유한다. Win32 메시지는 ImGui 백엔드로 전달하며, 창 크기가 바뀌면 설정 창의 back buffer를 다시 만든다. 닫기는 창을 숨기고 재사용한다. 변경 사항 저장에 실패하면 설정 창을 닫지 않고 오류를 표시한다.

ImGui v1.92.5 코어와 Win32/D3D11 백엔드는 `ThirdParty/imgui`에 포함되어 있다. MIT 라이선스 원문도 보관한다. 한글은 Windows에 설치된 맑은 고딕을 읽어 표시하며 폰트 파일을 재배포하지 않는다.

모델 텍스처는 재질에서 참조하는 압축된 내장 텍스처만 WIC로 읽는다. 내장 텍스처가 없을 때 외부 파일을 자동으로 찾는 기능은 제거되어 있다. 현재 비압축 내장 텍스처는 경고만 출력하며, 로딩에 성공한 SRV가 없으면 셰이더가 흰색으로 출력한다. 애니메이션 유무가 텍스처 로딩의 조건은 아니다.

WIC에 필요한 COM은 `WinMain`의 렌더 스레드에서 초기화하고 범위를 벗어날 때 해제한다.

## 11. 자율 걷기 연결

설정 창의 **자율 걷기** 탭에서 제자리 걷기 클립을 선택하고 활성화한 뒤 닫는다. 펫 창에 포커스를 준 뒤 `B` 키로도 같은 설정을 켜거나 끈다. 새 모델의 기본값은 꺼짐이며 사용할 걷기 클립이 없으면 이동하지 않는다. 기본 동작은 3~8초 대기하고 0.3초 동안 방향을 돌린 뒤 2~5초 걷고, 0.3초 동안 정면으로 돌아와 다시 쉬는 것이다. 실제 이동 속도는 `기준 속도 × Walk 배속 × 클라이언트 높이 / 600`이며 기본 기준 속도는 60픽셀/초다. 설정의 ‘이동 속도’는 기준 속도, ‘걷기 배속’은 클립과 이동에 공통으로 적용한다.

드래그·회전·수동 모드·설정 창 표시·미리보기·착지 중에는 이동을 중단한다. 다시 가능해지면 새 대기부터 시작한다. 회전 중에는 가로 이동을 멈추고 바닥 높이를 보정해 새 착지 이벤트가 반복되지 않게 한다.

걷는 시간을 모두 사용하면 제어기의 Returning에서 정면 보정 yaw로 돌아온 뒤 Waiting을 시작한다. 복귀 중에는 Idle을 재생하고 가로 이동을 멈춘다. ‘방향 전환 시간’을 시작·경계 반전·정면 복귀에 함께 사용하며, 0초이면 즉시 돌아온다. 사용자 quaternion 회전은 유지한다. B 키로 끄기나 잡기 등의 강제 중단은 복귀를 시작하지 않고 현재 각도에서 멈춘다.

`WindowPhysics::Prepare`가 중력과 접지를 계산하고, `WanderController`가 가로 이동과 방향을 정한 뒤, `WindowPhysics::Apply`가 최종 X/Y를 한 번에 적용한다. 공통 모델 행렬에는 사용자 회전 뒤 별도의 자동 Y축 회전이 추가된다. 화면 경계는 모든 자동 방향을 포함하는 바인드 기하의 보수적인 가로 범위를 사용한다.

이동 제어기의 Moving을 `PetBehaviorInput::walking`으로 전달한다. PetBehavior가 잡힘·낙하·착지 우선순위를 처리한 뒤 Walk를 반복 재생한다. 모델별 `PetAnimationSettings`가 UI·단축키·이동 제어기·저장기의 공통 설정이다. 자세한 좌표·모니터·클립 검사·버전 호환은 [자율 걷기 구현 현황](Autonomous_Walking.md)에 정리했다.
